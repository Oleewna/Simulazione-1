# Simulazione 1: Domande

## 1. 
- **Working tree:** cartella locale sul computer

- **Staging area:** un'area di preparazione intermedia, dove vengono elencate le modifiche selezionate che faranno parte del prossimo commit

- **Repository:** database locale in cui Git memorizza i commit

Dopo il `git add` le modifiche sono nella staging area e dopo il 'git commit' nella repository locale

## 2. 
- `git merge`: unisce le modifiche di un altro branch nel branch in cui ci si trova

- `git fetch`: scarica i dati della repo remota, mo non modifica i file di lavoro

## 3. 
- **Issue:** Apre o assegna una segnalazione sul portale per tracciare un bug da risolvere o una nuova funzionalità da sviluppare

- **Branch:** Crea un nuovo ramo di sviluppo isolato partendo dal codice principale

- **Commit:** Salva localmente le modifiche sul nuovo branch man mano che il codice viene scritto

- **Push:** Invia il branch locale e i relativi commit sul server remoto di GitHub

- **Pull Request:** Crea una richiesta formale su GitHub per proporre il merge del proprio branch all'interno del branch principale del progetto

- **Review:** Qualcuno esamina il codice della PR, inserisce commenti, testa le modifiche e approva il lavoro

- **Merge:** Una volta approvata, la Pull Request viene chiusa e il codice del branch viene integrato nel ramo principale
